# BOO-POS 優惠 / 折扣規格 v1

這份文件的目的不是只列「有哪幾種優惠」，而是整理成 BOO-POS 真的可以實作的規格骨架。

---

## 1. 系統目標

BOO-POS 的優惠不是只有折價。

它同時要支援：

- 滿額送禮
- 滿額折抵 / 滿額折扣
- 單品優惠
- 組合優惠
- 前台提醒
- 前台手動追加優惠

現場攤位的真實情境是：

- 有些優惠要自動算金額
- 有些優惠只要提醒店員
- 有些優惠要等攤主手動確認
- 有些優惠只限特定商品、特定場次、特定時段

所以 BOO-POS 的優惠系統，要把「條件」和「結果」拆開看。

---

## 2. 規則骨架

每一條優惠規則都應該由這五塊組成：

1. 規則類型
2. 觸發條件
3. 優惠結果
4. 前台行為
5. 疊加與優先順序

### 2.1 規則類型

MVP 建議先支援這四種：

- 滿額送禮
- 滿額折抵
- 單品優惠
- 組合優惠

第二階段再考慮：

- 買 X 送 Y
- 第二件特價
- 特定支付方式優惠
- 會員 / 預購限定優惠

### 2.2 觸發條件

可用條件先限制在這幾種：

- 訂單金額達門檻
- 購物車包含指定商品
- 指定分類商品達到數量
- 指定商品組合成立
- 指定場次 / 指定時間內成立

### 2.3 優惠結果

結果要分成兩種：

- 提醒型結果
- 價格型結果

提醒型結果：

- 提醒送贈品
- 提醒可選贈品
- 提醒符合某個活動條件

價格型結果：

- 折固定金額
- 打折百分比
- 單品改成特價
- 組合折抵

### 2.4 前台行為

每條規則要明確標記：

- 自動套用
- 只提醒，等待攤主確認
- 完全手動

建議預設行為：

- 滿額送禮：只提醒
- 滿額折抵：可自動套用
- 單品優惠：可自動套用
- 組合優惠：可提醒後確認

### 2.5 疊加與優先順序

這是最容易被忘記，但最重要的部分。

每條規則都要有：

- 是否可與其他優惠疊加
- 優先級

MVP 建議規則：

- 同一商品只能吃一種商品級優惠
- 整單級優惠最多套一種
- 贈品提醒可以和折抵並存
- 手動優惠優先級最高

## 3. 優惠類型定義

## 3.1 滿額送禮

### 用途

- 滿 500 送明信片
- 滿 800 送貼紙包
- 滿 1000 可選贈品 A 或 B

### 觸發條件

- 訂單總額達門檻

### 結果

- 不直接改價格
- 前台跳提醒
- 店員可手動加入贈品

### 後台欄位

- 規則名稱
- 啟用狀態
- 門檻金額
- 贈品內容
- 是否多選一
- 前台行為
- 是否計入贈品庫存
- 備註

### 前台按鈕 / 狀態

- `加入贈品`
- `略過`
- `已加入贈品`

---

## 3.2 滿額折抵

### 用途

- 滿 300 折 20
- 滿 500 折 50
- 滿 1000 打 9 折

### 觸發條件

- 訂單總額達門檻

### 結果

- 扣固定金額
- 或打折百分比

### 後台欄位

- 規則名稱
- 啟用狀態
- 門檻金額
- 折抵方式
- 折抵值
- 適用範圍
- 是否可疊加
- 前台行為
- 備註

### 前台按鈕 / 狀態

- `套用優惠`
- `取消套用`
- 已套用標籤

---

## 3.3 單品優惠

### 用途

- 指定商品特價
- 某商品現場限時價
- 指定品項折 10 元

### 觸發條件

- 購物車包含指定商品

### 結果

- 改單品價格
- 或折單品金額

### 後台欄位

- 規則名稱
- 啟用狀態
- 指定商品 / 分類
- 優惠方式
- 優惠值
- 是否限數量
- 是否限場次 / 時段
- 是否可疊加
- 備註

### 前台按鈕 / 狀態

- 多數可自動套用
- 若需確認則顯示 `套用優惠`

---

## 3.4 組合優惠

### 用途

- 刊物任選 2 本折 30
- 指定刊物 + 周邊折 20
- A + B 組合價

### 觸發條件

- 購物車內符合指定商品組合

### 結果

- 折固定金額
- 組合特價
- 顯示提醒

### 後台欄位

- 規則名稱
- 啟用狀態
- 組合條件
- 適用商品 / 分類
- 優惠方式
- 優惠值
- 是否可重複套用
- 前台行為
- 備註

### 前台按鈕 / 狀態

- `套用組合優惠`
- `取消套用`

---

## 4. 還要先想好的隱藏規則

這些不是優惠類型，但如果不先定義，之後一定會打架。

### 4.1 疊加規則

- 滿額折抵可不可以再吃單品優惠
- 單品優惠可不可以再參與組合優惠
- 手動折扣能不能和自動優惠並存

### 4.2 優先順序

建議順序：

1. 單品優惠
2. 組合優惠
3. 滿額折抵
4. 滿額送禮提醒
5. 手動優惠覆蓋

### 4.3 適用範圍

每條規則最好都能指定：

- 全單
- 指定商品
- 指定分類
- 排除商品
- 指定場次

### 4.4 使用次數限制

- 每單一次
- 每商品一次
- 每人一次
- 每場次一次

### 4.5 贈品庫存

滿額禮如果是正式商品，要先決定：

- 要不要扣庫存
- 要不要在紀錄中標成贈品
- 要不要出現在銷售紀錄報表

建議：

- 贈品當成特殊商品列
- 價格為 0
- 顯示 `gift` / `贈品` 標記

## 5. 後台設定頁需要的欄位

這裡是 BOO-POS 折扣設定頁的最小欄位集。

| 欄位 | 說明 |
| --- | --- |
| 規則名稱 | 使用者自己辨識用 |
| 規則類型 | 滿額送禮 / 滿額折抵 / 單品優惠 / 組合優惠 |
| 啟用狀態 | 開 / 關 |
| 觸發條件 | 門檻、指定商品、組合條件 |
| 優惠結果 | 送什麼、折多少、改成多少 |
| 適用範圍 | 全單 / 指定品項 / 指定分類 |
| 前台行為 | 自動套用 / 提醒確認 / 手動 |
| 疊加規則 | 可否與其他規則共存 |
| 場次限制 | 哪些場次有效 |
| 備註 | 給攤主自己看的說明 |

---

## 6. 前台結帳互動

### 6.1 顯示方式

不要整頁跳大彈窗。

建議使用：

- 結帳區上方的提示條
- 折扣摘要區
- 贈品狀態標籤

### 6.2 前台提示文案

例：

- `已達滿 NT$500，可加贈明信片`
- `符合刊物任選 2 本折 NT$30`
- `夜間小說已套用單品優惠`

### 6.3 前台操作入口

前台保留這 3 個入口就夠：

- `套用優惠`
- `加入贈品`
- `手動折扣`

---

## 7. MVP 建議

如果 BOO-POS 第一版要穩，建議先做：

- 滿額送禮
- 滿額折抵
- 單品優惠
- 組合優惠
- 手動折扣
- 手動加入贈品

先不要做：

- 自動最佳優惠計算
- 多層條件巢狀規則
- 同一單複雜疊加引擎
- 跨活動共享規則

---

## 8. Prototype 建議對應

折扣設定頁先不要只做一個「折多少」的表單。

建議至少能編輯：

- 規則類型
- 觸發條件
- 優惠結果
- 前台行為
- 疊加規則
- 備註

這樣之後接前台時，欄位不會整個重拆。

---

## 9. 結論

BOO-POS 的優惠系統，不該只被當成「折扣金額輸入框」。

它其實是一個：

- 規則判斷系統
- 前台提醒系統
- 手動覆蓋系統

只要先把規則類型、前台行為、疊加規則定清楚，後面不管是做後台設定還是前台提示，都會順很多。
