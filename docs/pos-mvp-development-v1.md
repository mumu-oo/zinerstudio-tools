# 擺攤 POS MVP 開發順序 v1

這份文件的目的不是討論美術，而是把目前已經確認好的原型，整理成真正可以開始開發的順序。

目前前提已定：

- 產品型態：平板用 POS App
- 支援平台：iPad / Android 平板
- 使用情境：同人展、市集、創作者擺攤
- 使用方式：離線優先、本機使用
- 資料策略：本機 SQLite，不做雲端同步
- 原型角色：HTML prototype 只用來確認 UI、流程與欄位，不是最終技術

---

## MVP 目標

第一版的目標不是做最完整，而是做出：

- 可以真的在展場結帳
- 可以管理商品
- 可以記錄已售
- 可以匯入預購名單並做取件
- 可以設定付款方式
- 沒網路也能用

只要做到這些，這個 App 就已經有實際價值。

---

## 不放進 MVP 的功能

這些功能有價值，但不建議第一版就做：

- 雲端同步
- 帳號系統
- 多人同時使用同一份資料
- 電腦版後台
- 跨裝置自動同步
- 完整自由拖曳的場次版面編排
- 白天 / 夜晚主題切換
- 進階防呆與大量提醒機制

說明：
這些不是不要做，而是先不放在第一個能用版本裡，避免開發範圍失控。

---

## MVP 核心模組

### 1. 商品管理

必做：

- 新增 / 編輯 / 刪除商品
- 品名
- 類型
- 自訂類型名稱
- 售價
- 標籤
- 庫存
- 已售
- 低庫存門檻
- 商品照上傳
- 無圖
- 預留替代圖示流程
- 備註

說明：
商品是整個系統的主檔，其他功能都會依附在商品資料上。

### 2. 前台販售

必做：

- 商品圖片牆選品
- 點商品加入購物清單
- 直式模式：先選商品，再進結帳
- 橫式模式：商品與結帳分割畫面
- 結帳清單顯示數量加減
- 顯示總金額
- 完成交易後寫入紀錄

說明：
前台的感受要偏「加法」，也就是點一下代表賣出一件，而不是一直強調庫存扣減。

### 3. 付款方式

必做：

- 後台自訂付款方式名稱
- 可新增 / 刪除 / 啟用 / 停用付款方式
- 前台顯示邏輯：
  - 啟用 1 種：顯示 1 顆按鈕
  - 啟用 2 種：顯示 2 顆按鈕
  - 啟用 3 種以上：顯示下拉選單
- 現金付款時展開現金計算機
- 快捷收款按鈕：`+1000`、`+500`、`+100`、`+50`
- 顯示應收、客付、找零

### 4. 庫存管理

必做：

- 搜尋商品
- 用分類下拉篩選
- 顯示庫存、已售、低庫存門檻
- 可直接修改數值
- 可全選、刪除、上架
- 低庫存整列變色

說明：
MVP 的庫存邏輯已定為單一庫存，不再拆場前庫存與現場庫存。

### 5. 預購管理

必做：

- 匯入 Excel / CSV 預購名單
- 搜尋姓名 / 訂單編號
- 篩選全部 / 未取 / 已取
- 顯示取件內容
- 可標記已取件 / 未取件

說明：
MVP 不處理本人 / 代理取件差異。

### 6. 備份與匯出

必做：

- 匯出商品資料
- 匯出交易紀錄
- 匯出預購名單狀態
- 匯出完整備份檔

建議格式：

- 匯入：Excel / CSV
- 匯出：CSV / JSON

## 建議開發順序

### 第 0 階段：原型收斂

這一階段其實已經接近完成。

重點：

- 把前台與後台 prototype 定到可接受
- 確認欄位名稱
- 確認直式 / 橫式行為
- 確認付款與庫存邏輯

完成標準：

- 不再大幅修改主要流程
- 不再頻繁推翻欄位設計

### 第 1 階段：技術底座

先做基礎骨架，不急著做漂亮動畫。

建議內容：

- Flutter 專案建立
- 路由 / 分頁骨架
- 共用設計 token
- SQLite 資料表建立
- 本機圖片儲存規則
- 匯入 / 匯出骨架

完成標準：

- App 能開起來
- 本機資料可新增、讀取、修改、刪除

### 第 2 階段：商品與設定

先把後台資料主檔做穩。

建議內容：

- 商品管理頁
- 付款方式設定頁
- 基本設定頁

完成標準：

- 可建立商品
- 可編輯付款方式
- 商品圖可選上傳 / 無圖

### 第 3 階段：前台販售

這是最核心的一段。

建議內容：

- 商品牆
- 購物清單
- 結帳頁
- 現金計算機
- 交易寫入

完成標準：

- 可完成一筆完整交易
- 可記錄付款方式
- 可更新已售

### 第 4 階段：庫存與預購

把現場工作需要的管理功能補齊。

建議內容：

- 庫存管理頁
- 低庫存提醒
- 預購匯入
- 預購查詢與標記取件

完成標準：

- 可直接在後台改庫存
- 可匯入名單並完成取件操作

### 第 5 階段：備份與整理

MVP 要能帶去現場，就一定要收尾。

建議內容：

- 匯出備份
- 匯出交易資料
- 匯出預購資料
- 錯誤狀態處理
- 基本防呆

完成標準：

- 展場前可手動備份
- 展場後可整理交易資料

## 建議第一個可用版本的頁面清單

前台：

- 商品選取頁
- 結帳頁
- 完成頁

後台：

- 商品管理頁
- 庫存管理頁
- 預購管理頁
- 付款方式設定頁
- 備份與匯出頁

---

## 資料優先順序

最先要穩定的資料：

1. 商品
2. 付款方式
3. 交易
4. 預購名單
5. 庫存

說明：
雖然庫存很重要，但它本質上還是依附在商品與交易之上，所以商品和交易資料一定要先穩。

---

## 第二階段功能候補

以下功能很值得保留到第二階段：

- 場次建立
- 場次版面配置
- 商品拖曳排版
- 自由調整商品區塊尺寸
- 依場次切換前台布局
- 白天 / 夜晚主題
- 更完整的防呆提示
- 更多統計報表

其中最值得優先考慮的是：

- 場次配置 / 攤位布局系統

因為這會是這套產品和一般 POS 拉開差距的地方。

---

## 一句話版開發策略

先把「離線可用、能結帳、能管商品、能做預購取件」的平板 App 做出來，再進化成有場次布局與更多個人化設定的完整版本。
